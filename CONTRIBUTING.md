# Contributing to JPF

JPF 0.2 needs evidence from real use more than abstract expansion.

## Useful contributions

- An anonymized account of a mistake the framework caught—or failed to catch
- A field or gate that changed a real decision
- A simplification that removes overhead without weakening accountability
- Better language for nontechnical participants
- Examples from industries, proposal types, or commercial structures not yet represented
- Compatibility notes for common document, spreadsheet, CRM, proposal, or agent tools

## Before opening an issue

- Remove buyer-confidential, partner-confidential, personal, pricing, credential, and proprietary information.
- Distinguish observed facts from interpretation.
- Describe the pursuit size, number of participants, time pressure, and tools used when those details matter.
- State whether the suggestion changes the core framework, a template, the AI skill, or only explanatory wording.

## Feedback prompts

1. What did JPF make visible earlier than your normal process?
2. What remained ambiguous?
3. Which step felt disproportionate to the risk?
4. Did one authoritative register reduce or add reconciliation work?
5. Could the approved proposal transition into delivery without reinterpreting commitments?
